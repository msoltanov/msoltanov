# Contributing to Mekan's Desk

Mekan's Desk is a Node.js generator for a GitHub profile README and its images.
The approved profile design remains the display contract.

## Applicable guides

This project uses Mekan Soltanov's Style Guides library. A sibling checkout of
that library is `../styleGuides`. The applicable files are:

- `js-style-guide.md` for JavaScript.
- `style-guide.md` for HTML and CSS.
- `JSON-STYLE-GUIDE.md` for configuration and stored documents.
- `markdown/MARKDOWN-STYLE-GUIDE.md` for documentation.
- `yaml/YAML-STYLE-GUIDE.md` and `yaml/YAML-GITHUB-ACTIONS-GUIDE.md` for CI.
- `BINARY-FORMAT-CODEC-GUIDE.md` for the activity cache.

Repository requirements take precedence over the general guides. The exceptions
in this file are limited to the stated files and contracts. They do not exempt
other source files from the checks.

## Local checks

CI uses Node.js 24 and Python 3.13. The npm lockfile pins JavaScript
dependencies. `requirements-style.txt` pins the Python style tools.

1. Install the JavaScript tools with `npm ci --ignore-scripts`.
2. Install the Python tools with
   `python -m pip install -r requirements-style.txt`.
3. Run `npm test`.
4. Run `npm run check`.

The check command covers source quality, formatting, YAML, Markdown, JSON
schemas and generated images. It does not collect live private statistics or
publish changes.

The optional `npm run check:preview` command checks the running local demo at
`http://localhost:4173`. The preview files and architecture notes under `docs/`
stay local under the existing ignore rules. CI checks the published maintenance
guide without requiring those files.

The HTML checker permits the generated profile's H3 headings and GitHub's legacy
alignment attributes. Document metadata, duplicate identifiers and inline styles
remain subject to its checks.

ESLint uses a scoped override for `minimatch` 11.0.1 to address
`GHSA-g3hv-75wg-m249`. The tooling tests check module discovery and error
reporting against the patched matcher. Remove the override after ESLint adopts a
corrected dependency.

## Source conventions

- Use native ESM and named exports in application modules.
- Keep explicit `.mjs` import extensions because Node.js resolves these modules
  without a bundler.
- Use the project's formatter and lint configuration.
- Keep source comments and JSDoc absent, as required by the repository rules.
- Keep existing tests for unavailable data, malformed input and privacy
  boundaries.
- Keep credentials in environment variables or Actions secrets.

Tool configuration files can use default exports when their consumers require
that interface. This exception does not apply to application modules.

Generated SVG path literals, accessible descriptions and other fixed image
geometry can exceed the normal line width. Splitting their contents can change
generated bytes. The formatter still owns the surrounding JavaScript layout.

Control-byte regular expressions are intentional in input and XML validation.
Their lint exceptions are limited to the validators that reject those bytes. The
GraphQL `__typename` field follows GitHub's external contract. Default imports
from external packages follow those packages' published APIs.

The activity collector updates its shared `cache` parameter to retain completed
history when its deadline expires. That mutation and its checkpoint test are
limited exceptions in `scripts/activity.mjs` and `test/generate.test.mjs`. Other
parameters remain protected from mutation.

The local preview uses native module scripts, which require `type="module"`. Its
600px CSS breakpoint matches the responsive picture-source contract. Base
element selectors in its CSS layer style generated GitHub markup. The component
selectors remain class-based.

## Configuration contracts

`config/profile.json` and `data/stats.json` have JSON Schema contracts under
`schemas/`. `node scripts/validate-data.mjs` checks them without network access.
Runtime validation still rejects invalid settings before data collection.

Existing configuration keys and stored enum values retain their released names
and casing. This includes `animated`, `enabled`, `github-profile` and the uptime
sources. Renaming those values to satisfy a general naming rule would break the
format. Any future rename needs a migration and a versioned schema.

The npm manifest and lockfile follow npm's external contract. JSON Schema
keywords follow the JSON Schema contract. GitHub responses retain GitHub's
external field names at the collection boundary. Ignored local API snapshots
retain their external response shapes.

## Generated profile exceptions

`README.md` is the public profile surface, not a conventional project manual. It
deliberately starts with the illustrated greeting and uses H3 section titles. It
has no text H1. The profile uses HTML pictures, native links and a toolbox table
because those elements preserve the approved GitHub layout and theme behavior.

Only `README.md` uses `.markdownlint-profile.json`. That configuration permits
its heading structure and a fixed HTML element list. Generator boundary comments
are also permitted in that profile file. Technical documentation uses
`.markdownlint.json` without those exceptions. The generator owns README
sections between markers. Do not format generated sections by hand or run
Prettier over this file.

SVG and GIF files under `assets/` are generated output. Their XML, text safety,
dimensions, frame counts, loop duration and size limits are checked
independently of source formatting. The statistics snapshot keeps deterministic
generator formatting.

## Activity cache contract

The cache is a disposable optimization, not the source of profile totals.
`data/stats.json` retains the last known aggregate statistics separately.

Version 1 uses this byte layout:

| Offset | Length          | Value                                                |
| ------ | --------------- | ---------------------------------------------------- |
| 0      | 4 bytes         | ASCII magic `ACC1`                                   |
| 4      | 12 bytes        | Random AES-GCM initialization vector                 |
| 16     | 16 bytes        | AES-GCM authentication tag                           |
| 32     | Remaining bytes | AES-256-GCM ciphertext of gzip-compressed UTF-8 JSON |

All header fields are byte arrays, so they have no integer byte order.
HKDF-SHA256 derives a 32-byte key from `PROFILE_STATS_TOKEN`. Its salt is
`alabay-code-profile` and its context is `activity-cache-v1`. The JSON document
contains `version`, `authorId`, `commits` and `heads`. Each commit stores its
OID, additions, deletions and parent count. Each head maps an OID to indexes in
the commit array. `schemas/cache.schema.json` defines the decoded payload.

Encrypted files have a 16 MiB limit. Decompressed JSON has a 64 MiB limit. The
payload permits at most one million commits and one hundred thousand heads. Each
head permits at most one million indexes. The author identifier has a
1024-character limit. Reads check these limits before accepting data. Writes
reject oversized data before replacing an existing cache.

| Version                               | Read policy                              | Write policy      |
| ------------------------------------- | ---------------------------------------- | ----------------- |
| `ACC1` and JSON version 1             | Read after authentication and validation | Current format    |
| Unknown, malformed or over-limit data | Discard and rebuild                      | Never reinterpret |

The committed version-1 fixture contains synthetic identifiers and a public test
token. It exists only for compatibility tests. Production encryption uses a
random initialization vector for every write. Ciphertext is not a canonical
representation for hashing or equality.

## CI and publication

The check workflow runs on pull requests and pushes with read-only permissions.
The update workflow uses the repository's default branch and runs near Ashgabat
midnight. Scheduled Actions runs can be delayed. Fresh private activity requires
the `PROFILE_STATS_TOKEN` Actions secret. Public collection uses the built-in
token, with an anonymous fallback.

Keep changes within the user-authorized scope. Publishing or changing repository
settings is separate from local checks.
